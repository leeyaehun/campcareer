# Monthly product review

Month: `YYYY-MM`  
Owner:

## Evidence review

- What grew, and which acquisition source or query explains it?
- What declined, and is the cause product behaviour, index coverage, data
  freshness, performance or an incident?
- Which entity paths produce Decision Sessions and Compare views?
- What do users actually use, and what is repeatedly ignored?
- Which searches have no results or weak result continuation?
- Which feedback/data issues repeat, and what source/change trace is required?
- What performance, error or accessibility evidence changed?
- Which core URLs are indexed, intentionally noindex, crawled-not-indexed or
  still unknown in Search Console?
- Which legacy landing pages still bring useful users into a current Career,
  Country, Degree or Education journey?

## Core-journey design review

Inspect Homepage, Career, Country, Degree, Education, Compare, filters and
mobile. For each observed issue, record whether the user can understand the
page, see important metrics, understand the next action, use filters and
Compare, see sources without losing hierarchy, and complete the page on a
small screen. Use [PRODUCT_DESIGN_REVIEW.md](../design/PRODUCT_DESIGN_REVIEW.md)
for the detailed record.

Before removing or rebuilding a public feature, inspect usage, funnel,
feedback, errors and search behaviour. Product reaction follows observed
behaviour, repeated behaviour, user feedback, search data, then founder
intuition.

Do not approve a broad redesign, new page family, country expansion or revenue
feature from this review without the applicable gate in
[PHASE_9_MASTER_OPERATING_SYSTEM.md](../PHASE_9_MASTER_OPERATING_SYSTEM.md).
